# **Intelligence Repository (مستودع الاستخبارات المركزي)**

## 1. الهدف من المستودع
إنشاء قاعدة بيانات مركزية تمثل "العقل المدبر" (Brain) لمنصة **Dragon R1**. هذا المستودع مسؤول عن استقبال، تنظيف، تخزين، وتحليل جميع البيانات الواردة من وكلاء جمع البيانات (Data Collectors)، وجعلها جاهزة للاستهلاك الفوري بواسطة فرق التنفيذ (Execution Agents)، بالإضافة إلى تسجيل النتائج واستنتاجات النظام لتحقيق التعلم المستمر.

## 2. الهيكلية المعمارية (Architecture Stack)

بناءً على متطلبات **Dragon R1** من سرعة عالية، تحليل سياقي، وارتباطات معقدة، سيتم بناء Intelligence Repository باستخدام بنية هجينة (Hybrid Polyglot Persistence):

### أ. PostgreSQL (القلب النابض للبيانات المنظمة)
- **الهدف:** تخزين المهام، إعدادات الوكلاء، بيانات الجلسات، التوثيق القانوني (Chain of Custody)، وتقارير الأداء.
- **التقنيات الإضافية:** 
  - `PostGIS` (إذا استدعت الحاجة تحليلات جغرافية للتهديدات).
  - `pgvector` لتخزين الـ Embeddings في حال أردنا دمج الـ Vector DB داخل بيئة واحدة لتقليل التعقيد.

### ب. Neo4j أو SurrealDB (تحليل الارتباطات - Graph DB)
- **الهدف:** رسم الخريطة الهجومية (Attack Graph) وتتبع مسار الهجوم (Attack Path).
- **الاستخدامات:**
  - ربط عنوان IP محدد بثغرة معينة، ببيانات دخول مسربة، بوكيل محدد.
  - يستطيع الـ Agent طلب مسار الاختراق الأمثل عبر استعلام `Cypher`.

### ج. Elasticsearch / OpenSearch (البيانات السريعة وغير المنظمة)
- **الهدف:** تخزين وتحليل الـ Logs، مخرجات الأدوات الخام (مثل ملفات Nmap XML الكبيرة، نتائج Fuzzing)، وسرعة البحث الذكي فيها.

### د. Redis (طبقة التخزين المؤقت والرسائل)
- **الهدف:** تخزين الـ State اللحظية، وإدارة طوابير المهام السريعة (Message Queue) بين الـ Agents (مثل نشر التحديثات للـ Frontend عبر WebSockets).

## 3. تدفق البيانات (Data Workflow)

1. **Ingestion (الإدخال):** 
   - يقوم فريق **Data Mastery Team** بجلب المعلومات.
   - يتم تمريرها عبر `Verification Layer` للتأكد من خلوها من الهلوسة أو التشوه.
2. **Structuring (التنظيم):**
   - تُرسل النصوص الطويلة ليتم تحويلها إلى Vectors وتخزن لدعم محرك الـ RAG.
   - الكيانات (IPs, Ports, Services) تُرسل للـ Graph DB.
   - بيانات المهمة والحالة تُحدث في PostgreSQL.
3. **Consumption (الاستهلاك):**
   - يقوم الـ **Dragon Agent** (المعنى بالتخطيط) بإرسال استعلام مجمع (GraphQL أو tRPC) لجلب ملخص عن الهدف.
4. **Enrichment (الإثراء المستمر):**
   - بعد كل هجوم ناجح أو فاشل، يتم حفظ الـ Payload المستخدم وتأثيره (Feedback Loop) لتعزيز الـ RLHF ولتحسين الاختيار التلقائي في المستقبل.

## 4. تصميم الـ API (الواجهة البينية للوكلاء)
سيتم بناء طبقة وسيطة (Data Gateway) باستخدام **FastAPI** أو **Rust (Axum)** تمتلك واجهات قياسية (GraphQL / REST) تسمح للوكلاء بـ "الاشتراك" (Subscribe) في تغييرات معينة، مثل التنبيه عند اكتشاف ثغرة جديدة، ليقوم وكيل آخر باستغلالها فوراً.
